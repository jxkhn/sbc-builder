# Debian SBC image builder

Builds bootable SD-card images for Rockchip SBCs from **mainline Linux + mainline
U-Boot + plain Debian** (mmdebstrap). Nothing in the result depends on Armbian at runtime:
no Armbian packages, apt repos, cron jobs, motd scripts or forked `base-files`.

## Current state

Early and only lightly tested. Two boards have been tested on real hardware with a bare image
(boot and networking only; no other peripherals checked):

- **Radxa ROCK 3A**: boots, Ethernet works.
- **Radxa ZERO 3E**: boots, Ethernet works.

All other boards are **untested**: they have board files, but no image has been built and booted
for them yet. Reports are welcome.

|---|---|---|---|
| `rock-3a` | RK3568 | tested (boot, networking) | M.2 NVMe needs the PCIe 3.0 PHY timeout patch (shipped) |
| `radxa-zero3e` | RK3566T | tested (boot, networking) | |
| `radxa-zero3w` | RK3566T | untested | |
| `rock-3b`, `radxa-e25` | RK3568 | untested | |
| `rock-3c` | RK3566T | untested | |
| `rockpi-s` | RK3308 | untested | |
| `rockpi-e`, `rockpi-e-v3` | RK3328 | untested | `TPL_SOURCE=uboot BL31_SOURCE=tfa` gives a blob-free boot chain |
| `rock-5a`, `rock-5b`, `rock-5b-plus`, `rock-5c` | RK3588(S) | untested | SPI flash boots before the SD card |

All boards share one kernel build (`rockchip64`). Each board file pins the U-Boot version and DDR/BL31 blobs
Armbian uses for that board or its closest sibling. Adding a board is one small file (see `config/boards/`).

```
sudo ./build.sh                          # menu, like Armbian's compile.sh
sudo ./build.sh build CONFIG=zero3e      # same thing, non-interactive
./build.sh options                       # the whole option tree with defaults
```

## What gets built

| Stage    | Output                                                      | Replaces from Armbian |
|----------|-------------------------------------------------------------|-----------------------|
| `kernel` | `linux-image-<ver><suffix>` via `make bindeb-pkg`, plus `<prefix>-linux-image-<family>` metapackage | `linux-image-edge-rockchip64`, `linux-dtb-*` |
| `uboot`  | `<prefix>-u-boot-<board>`: mainline U-Boot + `<prefix>-u-boot-install` | `linux-u-boot-*` |
| `bsp`    | `<prefix>-bsp-<board>`: first boot, kernel hook, boot config, zram, journald, governor, motd | `armbian-bsp-cli-*` |
| `rootfs` | Debian via mmdebstrap, all of the above installed            | Armbian rootfs, `base-files` fork |
| `image`  | `output/images/*.img.xz` + `.sha256`                         | |

Each stage fingerprints its inputs and skips itself when nothing changed (`FORCE=yes` rebuilds).
`STAGES="kernel uboot bsp"` builds only the packages, e.g. for your apt repo.

**Boot chain:** U-Boot at sector 64 → U-Boot's standard boot finds `/boot/extlinux/extlinux.conf` on
the root partition → kernel + initrd + DTB (+ overlays). `extlinux.conf` is generated by Debian's
`u-boot-menu` on every kernel install; the board settings come from the BSP package
(`/usr/share/u-boot-menu/conf.d/50-<prefix>-board.conf`), root= from `/etc/fstab`. There is no
`boot.scr`, `armbianEnv.txt` or `uInitrd`.

## The option tree

Options are grouped like Armbian's menu: **Target, Kernel, Bootloader, Root filesystem,
Users & access, Tweaks, Image, Armbian import**. Indented options only appear when the
option above makes them relevant (e.g. `KERNEL_CONFIG_FILE` only when `KERNEL_CONFIG=file`).
Everything is declared once in `lib/options.sh`, so the menu, `./build.sh options`, saved
configs and `KEY=value` overrides always agree.

Configs are plain shell files in `userpatches/config-<name>.conf`; save them from the menu
or start from `userpatches/config-example.conf`. Passwords are stored as SHA-512 hashes.

Highlights:
- `KERNEL_SOURCE=mainline | debian | debian-backports | prebuilt`
- Kernel config: every base config gets `config/kernel/fragments/common.config`, `net-server.config` (policy routing,
  nftables/iptables with NAT, WireGuard, bridges, VLANs; needed by Tailscale, Docker and firewalls) and the
  family fragment merged on top.
- `KERNEL_HEADERS=auto`: builds linux-headers for DKMS only on arm64 hosts. On x86 it needs `libssl-dev:arm64`.
- `KERNEL_CONFIG=defconfig | armbian | file`. For exact parity with a running unit:
  `ssh unit zcat /proc/config.gz > userpatches/kernel/zero3e.config` and use `file`.
- `IMAGE_HOSTNAME=zero3e-{MAC}`: unique hostnames per board on first boot
- `FLEET_REPO_URL` / `FLEET_REPO_KEY`: your own apt repo for kernel/u-boot/bsp updates
- `FDT_OVERLAYS="rockchip-rk3566-spi3-m0-cs0-spidev.dtbo"` (Armbian's `overlays=`)

## Step 2: reuse Armbian's kernel work (optional)

```
sudo ./build.sh armbian-import CONFIG=zero3e
```

This copies Armbian's kernel patches, extra device trees, DT overlays and kernel config
for your kernel series into `userpatches/armbian/` as **plain source files** with a
provenance note. `ARMBIAN_REF=auto` finds the newest Armbian commit that still has your
series; Armbian deleted `rockchip64-7.2` on 2026-10-06 when edge moved to 7.3.

It also writes an inventory that sorts every patch into `board` / `soc` / `generic` /
`other-board` by the files it touches, plus `exclude-suggested-<board>.list`. Copy what you
agree with into `userpatches/kernel/exclude.list`. For the Zero 3E with 7.2 the result
is small: 3 patches touch its DTS/dtsi and 4 are RK356x driver changes. The rest is for
other boards or generic.

Then set `KERNEL_ARMBIAN_PATCHES=yes` (and `KERNEL_CONFIG=armbian` if you want their config).

## Fixes shipped with the builder (`patch/kernel/`)

Applied after Armbian's patches and before yours (`userpatches/kernel/exclude.list` can skip them):

- `rockchip64/general-stmmac-workaround-dma-reset.patch`: imported unchanged from Armbian (rockchip64-7.2/7.3,
  Paolo Sabatino), the same workaround Armbian's own kernels carry. On `Failed to reset the dma`, the Ethernet
  driver logs a warning and opens the interface anyway.

- `rockchip64/general-phy-rockchip-snps-pcie3-longer-sram-init-timeout.patch`: the RK3568/RK3588 PCIe 3.0 PHY driver
  waits only 500 µs for the PHY to start after reset. On a ROCK 3A that regularly timed out at boot (`lock failed ...
  check input refclk`), so the M.2 NVMe was missing, although re-probing later worked. Now it waits up to 20 ms.

`patch/kernel/experimental/` holds two patches written while debugging a Zero 3E that turned out to have
defective Ethernet hardware. They are not applied by default; see the README there.

**Zero 3 boot chain:** the board configs pin what Armbian ships for these boards: U-Boot v2025.10 with DDR
v1.21 and BL31 v1.44, from Armbian's rkbin mirror at build time. Override with `UBOOT_VERSION=latest`
and `RKBIN_REPO=...` if you want to try newer ones.

## Your own changes (`userpatches/`)

| Path | Effect |
|------|--------|
| `kernel/<family>/*.patch`, `kernel/<family>-X.Y/*.patch` | applied after Armbian's; `dt/` and `overlay/` subdirs work too |
| `kernel/<family>.fragment` | kconfig fragment merged last |
| `kernel/exclude.list` | patch / DTS / overlay names (globs) to skip |
| `u-boot/<board>/*.patch`, `u-boot/<board>.config` | U-Boot patches / kconfig fragment |
| `bsp/` | files added to the BSP package (updatable over apt) |
| `overlay/` | files copied into the rootfs once |
| `customize.sh` | runs at the end of the rootfs build: `$1` = rootfs, all options exported |
| `packages.list` | extra packages |
| `boards/<board>.conf` | your own boards |

First-boot hooks: executables in `/etc/<prefix>/firstboot.d/` run once before networking
(ship them via `userpatches/overlay/`).

## Build host

Debian bookworm/trixie or Ubuntu 22.04+, x86_64 or arm64. Missing packages are listed and can be
installed for you. Building the rootfs on x86 needs arm64 emulation: `qemu-user-binfmt`
on trixie, `qemu-user-static binfmt-support` on bookworm/Ubuntu. Run as `sudo`. Compiles
and caches run as your user, and only mmdebstrap and the image step use root.

**Ubuntu 26.04+ hosts** ship the Rust coreutils (uutils), and their `install -D` has a race
([LP#2151166](https://bugs.launchpad.net/ubuntu/+source/rust-coreutils/+bug/2151166)) that breaks
the kernel's parallel `dtbs_install`. The builder detects uutils and puts a retrying `install` wrapper
first in PATH for the kernel build (`INSTALL_SHIM=auto|yes|no`).

## Updating the fleet

Put `output/debs/**` into an apt repo (aptly/reprepro), set `FLEET_REPO_URL`, and the boards
pick up new kernels through the metapackage. U-Boot updates are installed as files; they
are written to the card only with `UBOOT_AUTOUPDATE=yes`, or by hand with
`sudo <prefix>-u-boot-install`. The installer refuses to run if a partition overlaps U-Boot.

## Migrating a running Armbian unit (instead of reflashing)

Test on one board with a spare card first. The list below comes from auditing an Armbian bookworm install on a ROCK Pi S.

1. `sudo ./build.sh build CONFIG=<cfg> STAGES="kernel uboot bsp"`, then copy the debs over.
2. On the board: `sudo apt install ./<prefix>-bsp-*.deb ./linux-image-*.deb ./<prefix>-linux-image-*.deb ./<prefix>-u-boot-*.deb`.
   Check `/boot/extlinux/extlinux.conf`. It takes priority over `boot.scr` once the new U-Boot is in place.
3. Check the first partition starts at sector 32768 or later (`cat /sys/class/block/mmcblk*p1/start`), then
   run `sudo <prefix>-u-boot-install` and reboot. Check `uname -r`.
4. Remove Armbian:
   - packages: `apt purge armbian-bsp-cli-* armbian-config armbian-firmware linux-image-edge-rockchip64 linux-dtb-edge-rockchip64`
   - apt: `/etc/apt/sources.list.d/armbian*.sources`, `/etc/apt/preferences.d/armbian`, `/etc/apt/apt.conf.d/02-armbian-postupdate`
   - **base-files is Armbian's fork** (`26.8.3-12.4+deb12u15-bookworm`): after removing the repo,
     `apt install --allow-downgrades base-files/<release>`. This restores `/etc/os-release`, `issue`, `issue.net`
     and the dpkg origin.
   - leftovers: `/etc/cron.d/armbian-*`, `/etc/cron.daily/armbian-*` (one fetches quotes from github.armbian.com daily),
     `/etc/update-motd.d/*armbian*` and the other Armbian motd scripts, `/etc/profile.d/armbian-*`,
     `/etc/systemd/system/logrotate.service` (ramlog override), `/etc/initramfs/post-update.d/99-uboot`,
     `/etc/armbian*`, `/etc/dpkg/origins/armbian`, `/etc/default/armbian-*`, `/boot/boot.cmd`, `boot.scr`, `armbianEnv.txt`, `uInitrd*`, `dtb*`
   - conffiles Armbian modified (from `dpkg --verify`): logrotate.conf and logrotate.d/*, journald.conf,
     sysctl.conf, default/useradd, initramfs-tools/initramfs.conf. Restore each one:
     `f=/etc/sysctl.conf; p=$(dpkg -S $f | cut -d: -f1); sudo rm $f; sudo apt-get install --reinstall -o Dpkg::Options::=--force-confmiss $p`.
     The sudoers `?` entries only mean the check could not read the file, not that it was changed.

Build with the same `RELEASE` the unit already runs (e.g. `RELEASE=bookworm`) when migrating in place.

## Notes and limits

- **Blobs:** RK3566/RK3308 DDR init comes only as a Rockchip binary (rkbin). BL31 can be built from
  upstream TF-A for RK3566 (`BL31_SOURCE=tfa`), but not for RK3308. Both the Zero 3 boards (pinned versions) and the
  ROCK Pi S (UART0 DDR blob) take their blobs from Armbian's rkbin mirror, at build time only (`BOARD_RKBIN_REPO`).
- **Kernel image:** the BSP's kernel hook stores `/boot/vmlinuz-*` uncompressed. U-Boot's limit for
  gzip'd kernels on RK3308 is 32 MiB. As a side effect, `dpkg --verify` flags that file.
- **ZERO 3W:** AIC8800 Wi-Fi revisions need an out-of-tree driver (Armbian's DKMS extension).
- **Debian stock kernel** (`KERNEL_SOURCE=debian`): convenient, but check that your U-Boot boots it with
  `booti`, and it ships no Armbian overlays.
